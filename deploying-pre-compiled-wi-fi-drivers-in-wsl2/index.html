Guide: Deploying Pre-Compiled Wi-Fi Drivers in WSL2

Scenario: You have built a custom WSL2 kernel with wireless support enabled (CONFIG_CFG80211, CONFIG_MAC80211) and successfully compiled the out-of-kernel driver on a development machine. Instead of re-compiling the driver stack on every new WSL2 instance, you can package the compiled module hierarchy into a zip archive and deploy it instantly.

What is inside the ZIP file?

The backup zip file preserves the exact kernel tree directory structure required by Linux:

  • /lib/modules/<kernel-version>/kernel/drivers/net/wireless/ — Contains the compiled driver binary file (e.g., 8821au.ko).
  • /lib/modules/<kernel-version>/ — Core dependency mapping files (modules.dep, modules.alias, etc.) generated during the initial compilation.

Step-by-Step Restoration Guide

Use these steps to restore the pre-compiled driver on any target Windows machine running a clean WSL2 Linux distribution.

Step 1: Configure the Custom Kernel on Windows

Ensure the Windows host .wslconfig file (located in your Windows user profile directory: C:\Users\<Windows_User>\.wslconfig) points directly to the custom compiled, wireless-enabled kernel binary:

[wsl2]
kernel=C:\\path\\to\\your\\custom\\vmlinux-wifi

Step 2: Extract and Move Modules into WSL2

  1. Open your WSL2 Linux terminal.
  2. Navigate to the directory where your backup zip file or extracted module folder is located (e.g., a shared mount path or your home directory).
  3. Copy the entire pre-compiled structure into the system module directory using superuser privileges:
# Ensure the system module root directory exists
sudo mkdir -p /lib/modules/

# Copy the pre-compiled module folder into the system path
# (Replace <kernel-version-folder> with your actual folder name, e.g., 6.18.40.1-microsoft-standard-WSL2+)
sudo cp -r <kernel-version-folder> /lib/modules/

Step 3: Refresh Kernel Module Dependencies

Force Linux to re-index its module directory and register the newly dropped driver binary:

sudo depmod -a

Step 4: Restart the WSL2 Environment

For the kernel to cleanly initialize the drivers and bind them to the passed-through USB device, execute a full environment reset:

  1. Open a standard Windows PowerShell window and stop the WSL instance:
    wsl --shutdown
  2. Attach the physical USB Wi-Fi adapter to WSL2 using your standard usbipd command workflow.
  3. Relaunch your WSL2 Linux distribution terminal.

Step 5: Verify and Activate the Interface

Confirm that the kernel picked up the hardware layer automatically without errors:

# Verify the wireless physical layer is detected
iw dev

# View all available network interfaces
ifconfig -a

Bring the newly created interface online (replace wlan0 with your specific interface name if it uses a predictable wlx... identifier):

sudo ifconfig wlan0 up
