Hackthebox Reactor Walkthrough

h4ck3rfirst October 5, 2026

Welcome to my writeup for Reactor, an easy-difficulty Linux machine on Hack The Box. This box provides a fantastic look into modern web ecosystem vulnerabilities, data extraction, and subsequent pivot methodologies. We will move from unauthenticated Remote Code Execution (RCE) in a cutting-edge web framework to database cracking, culminating in a pivot to a system user shell.

Recon

Every successful penetration test begins with gathering information about the target. We start by running an aggressive Nmap scan covering all ports to discover active services.

  • Port 22/tcp: Open - OpenSSH 9.6p1 (Ubuntu Linux)

Port 22 gives us an entry point if we manage to acquire valid SSH credentials down the line. However, our primary target is Port 3000. The scan highlights HTTP fingerprint components unique to Next.js (x-nextjs-cache, X-Powered-By: Next.js). This confirms that an active web application is our immediate point of entry.

Enumeration

3000

Nuclei scan flags a critical finding: CVE-2025-55182.

CVE-2025-55182 (nicknamed “React2Shell”) is a maximum-severity (CVSS 10.0) unauthenticated remote code execution (RCE) vulnerability that affects the React Server Components (RSC) ecosystem and downstream frameworks like Next.js

Using the blueprint provided by the React2Shell vulnerability, we intercept or construct a malicious POST request targeting the Next.js backend. We embed a Node.js payload inside the _response prefix object to execute id and capture its response inside the error digest.

Attempting to call require('child_process') drops a standard ReferenceError: require is not defined restriction.

the global Node environment tree directly to target the main running application module (process.mainModule), which retains access to the base module system

The server returns an empty byte array payload (Uint8Array(0)), verifying that the underlying operating system handled the chmod execution without throwing runtime execution errors.

shell as root

The binary file attributes confirm success: the file permissions successfully changed to -rwsr-sr-x, meaning it is now an active SUID binary owned by root.
